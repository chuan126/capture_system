# 手动RTK端点记录验收标准

核对日期：2026-08-27

## 1. 验收范围

本次变更只调整隧道入口和出口RTK端点的触发方式。连续RTK样本、点云采集、净空计算、暂停区间、数据回放、报告导出和任务永久删除保持原有职责。

## 2. 功能验收

1. 选中待执行任务后、开始采集前，同一个RTK按钮显示“入口RTK”；点击后无论定位是否有效都保存入口快照并禁用重复推进。
2. RTK离线不作为开始采集的阻塞条件；RTK状态仍正常显示和诊断。
3. 开始采集后，同一个RTK按钮按设备端状态继续：已有入口快照时显示“出口RTK”；未提前记录入口时仍显示“入口RTK”，不阻塞采集。
4. 端点命令必须经过FastAPI、ROS 2任务Service和记录器，浏览器不得直接写经纬度。
5. 最近RTK快照有效且新鲜时，`rtk_endpoints`写入对应`entry`或`exit`记录，任务端点状态更新为`confirmed`。
6. RTK缺失、无效或过期时，仍保存本次按钮时间和即时快照，端点状态更新为`unconfirmed`并切换到下一端点；不得把无效快照描述成有效坐标。
7. 重复成功记录允许更新最终端点，且每次尝试在`event_rtk_snapshots`和任务事件中留痕。
8. 停止命令固定测量边界后立即收尾，不抓取RTK、不进入等待阶段，并释放活动任务槽。
9. 未记录入口或出口RTK不阻塞停止，最终状态保持`not_requested`或`unconfirmed`并产生明确告警。
10. 已完成且出口未记录的任务允许在没有其他活动任务时补录出口RTK；补录只追加端点快照和事件，不修改测量边界及正式样本。
11. 刚停止的任务在出口快照完成前保持选中；用户主动选择下一待执行任务后，旧任务缺少出口不得阻塞新任务入口RTK或开始采集。

## 3. 数据完整性验收

1. `measurements.db.tmp`仍只在正常或异常收尾后原子改名为`measurements.db`。
2. `rtk_samples`继续保存连续RTK样本，不因端点手动化而停写或改变字段。
3. `clearance_samples`、`clearance_source_frames`、`imu_samples`及暂停区间的数量与时间边界不受端点命令影响。
4. 入口端点接受待执行任务以及当前活动任务；出口端点只接受当前活动任务。任务UUID、状态版本和幂等键必须校验。
5. 入口和出口角色不可混写，数据库仍最多各保留一个最终端点，同时保留完整尝试历史。
6. SQLite完整性检查、WAL检查点和记录计数在停止时继续执行。
7. 采集前入口快照保存到任务目录的`entry_rtk_snapshot.db`，写入使用完整同步和完整性检查；不得只保存在浏览器或进程内存。
8. 开始采集时把暂存入口快照和按钮时间原子导入`measurements.db.tmp`；提交成功后才删除暂存文件。启动失败时保留暂存文件供重试。
9. 停止后出口补录使用`BEGIN IMMEDIATE`事务打开既有`measurements.db`，校验任务UUID和完成标志，写入后执行WAL检查点与完整性检查。
10. 出口补录前后`clearance_samples`、`clearance_source_frames`、`imu_samples`、`pause_intervals`及`recording_counters`必须完全不变。

## 4. 控制与异常验收

1. 开始、暂停、继续和停止的原有状态转换及版本冲突保护全部通过。
2. RTK端点Service不可用时只禁用对应端点按钮，不影响其他可用任务控制。
3. 浏览器断线不终止设备端采集；重连后按设备端任务状态恢复按钮和端点状态。
4. 双击或网络重试使用同一幂等键时，不得产生两次任务状态转换。
5. 记录器不可用、数据库写入失败和任务版本过期均返回明确错误，不得在前端伪造成功状态。
6. 入口快照记录后、开始采集前重启任务管理器或记录器，入口状态和暂存快照仍可恢复；开始后正式数据库必须包含同一按钮时间与快照内容。
7. 已有其他活动任务时拒绝补录旧任务出口，但不得影响该活动任务及新任务自身的入口RTK记录。

## 5. UI与显示器验收

1. 单一RTK按钮与“开始采集、暂停/继续、停止”位于同一固定控制区，顺序为“开始、暂停/继续、入口/出口RTK、停止”。
2. 宽面板显示四列；窄任务侧栏自动改为顺序不变的两行两列，无横向滚动和文字遮挡。
3. 1366×768、1440×900、1920×1080和2560×1600视口下，任务主按钮与RTK按钮均可访问。
4. 桌面端RTK按钮高度不小于40 px；状态同时使用文字和颜色表达。
5. 未请求、记录中、有效快照、无效快照、入口到出口推进和“测量已封存、等待出口RTK”均有明确文字。
6. 使用键盘可以聚焦并触发按钮，禁用状态由原生`disabled`表达。

## 6. 回归与完成门槛

以下项目全部满足才可判定验收通过：

1. 前端TypeScript类型检查和任务控制源码测试通过。
2. 后端任务控制、ROS桥、记录器schema及任务管理器源码测试通过。
3. `interfaces`、`data_recorder`和`task_manager`在ROS 2 Humble下编译成功。
4. 前端设备静态构建成功。
5. 使用固定测试任务验证“采集前入口/采集中出口”三种组合：入口/出口均有效、入口无效出口有效、入口有效出口无效；并覆盖暂停时记录和缺失端点停止路径。
6. 使用既有任务数据库验证回放、TXT/PDF导出和历史入口/出口端点读取未回归。
7. 实机验收时记录RK3588上的命令响应、数据库收尾时间以及浏览器断线恢复结果；未连接实机时不得声称实机验收完成。
