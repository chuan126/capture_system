# 原始雷达本体系最低可信点簇净空算法

核对日期：2026-08-24

## 1. 目标与边界

正式算法直接处理 ODIN1 Lite 原始 `PointCloud2`，在单帧内寻找沿雷达 `+X` 高度轴最近、
同时具有空间连续支持的点簇。它不读取 IMU、里程计、四元数、姿态补偿结果或运动补偿结果，
从而隔离高速行驶时姿态和里程计漂移。输入仍是一帧跨约 94 ms 的扫描；本方案有意不进行
逐点时空配准，因此结果是原始雷达本体系观测量，不是世界坐标平面高度。

当前安装矩阵、测试和固定 MCAP 的数值范围共同支持 `+X` 为车辆向上方向。MCAP 没有已知高度
真值，不能替代现场轴向标定；部署必须复核轴向、安装高度和车辆遮挡。

## 2. 数据流

```text
/capture/lidar/points_raw
→ 布局与时间/frame检查
→ 有效点过滤
→ 围绕+X轴的圆柱ROI
→ X升序最低高度带
→ YZ网格八邻域连通分量
→ 点数/占用格/跨度支持判定
→ 最低可信簇X中位数
├→ /capture/clearance/result
└→ /capture/clearance/raw_diagnostics
```

正式输入默认 Topic 为 `/capture/lidar/points_raw`。消息必须是 little-endian，具有可访问的
XYZ FLOAT32 字段、非零源时间戳和非空 frame。`expected_frame_id` 默认为空，因为业务代码不
写死厂商 `device0`；空值表示接受现场实测的任意非空 frame，部署可显式收紧。

## 3. ROI

对有限且不为 `(0,0,0)` 的点 `p=(x,y,z)`，采用闭区间：

```text
min_detection_x_m ≤ x ≤ max_detection_x_m
y² + z² ≤ detection_radius_m²
```

默认半径为 1.0 m，高度范围为 `[1.0, 10.0]` m。固定 MCAP 在 0.225–0.227 m 存在持续近场
结构簇，因此沿用旧通用净空配置的 1.0 m 下界，而不采用旧隧道实验档的 0.20 m 下界。这是围绕高度轴的圆柱 ROI，避免把远处
侧壁和大 FOV 边缘混入“轴向最近”判定。半径是算法参数，可在 development 页面和离线回放
中扫描，不与 10°×10° 角度 ROI 混用。

## 4. 最低可信点簇

ROI 点按 `X` 升序。算法从最低点起构造闭合高度带
`[x_low, x_low + support_height_band_m]`。若带内点数不足则继续向上；否则把点投影到 `YZ`
平面，以 `spatial_grid_size_m` 量化并按八邻域求连通分量。

分量必须同时满足：

- 点数不少于 `min_support_points`；
- 占用网格不少于 `min_occupied_cells`；
- `Y` 或 `Z` 至少一轴跨度达到 `min_spatial_span_m`。

首个包含合格分量的最低高度带获胜。若同一带有多个合格分量，依次按较低 `X` 中位数、较低
最小 `X`、较小原始线性索引确定性选择。输出高度是获胜分量的 `X` 中位数；代表点必须是该
分量中的真实观测点，先选离中位数最近者，再以原始索引消歧。所有原始索引升序发布，便于
旁路预览关联。

## 5. 输出和无效语义

`ClearanceResult.lidar_to_top_m` 仅表示雷达到点簇的轴向距离。记录器使用任务开始时冻结的
`lidar_mount_height_m` 计算最终 `clearance_height_m`。最终高度位于包含边界的
`[clearance_threshold_m, clearance_upper_limit_m]` 时正常；严格低于下限或高于上限才异常。

`RawClearanceDiagnostics` 保存输入/有效/ROI/点簇计数，点簇 X 范围、中位数、代表点原始
XYZ、ROI 索引和点簇索引。它采用 best-effort QoS，只用于诊断及预览颜色，丢失不会影响
`ClearanceResult`。

无效原因包括：

| 原因 | 含义 |
| --- | --- |
| `INVALID_POINT_CLOUD_TIME` | 源时间戳为零 |
| `INVALID_POINT_CLOUD_FRAME` | frame 为空或不符合显式配置 |
| `INVALID_POINT_CLOUD_LAYOUT` | 字段、端序、步长或数据边界不兼容 |
| `NO_VALID_RAW_POINTS` | 没有有限非零原始点 |
| `NO_POINTS_IN_CYLINDRICAL_ROI` | 有效点存在，但圆柱 ROI 为空 |
| `INSUFFICIENT_ROI_SUPPORT` | ROI 总点数少于最少支持点 |
| `NO_SPATIALLY_SUPPORTED_CLUSTER` | 没有同时满足连续性条件的最低点簇 |

任何无效帧均发布 `valid=false` 和 `NaN` 高度，不沿用上一帧结果。

## 6. 旁路三色预览

补偿节点对每个原始输入点严格产生一个同顺序输出点并继承源时间戳，因此
`cloud_visualization` 可以用“精确时间戳 + 原始线性索引”给补偿 ENU 预览着色。全部有效扫描
点为蓝色，圆柱 ROI 覆盖为绿色；有效的最低可信点簇始终覆盖为红色，与任务状态和高度阈值无关。
诊断错帧、丢帧或点数不符时不得沿用旧索引，整帧退化为蓝色。预览从不反向参与计算。

## 7. 已退出正式链路的功能

原多平面 RANSAC、二次曲面、IMU/里程计姿态补偿和逐点运动补偿不再是正式净空前置条件。
补偿节点仍保留在线上 Launch 中，仅为局部 ENU 网页预览供数；厂商 SLAM 点云仍只用于 RViz2
和辅助诊断。旧 `ClearanceResult` 平面字段仅为记录/Web兼容保留，新算法不生成其语义。
