# 运动补偿算法

实现位置：`ros2_ws/src/motion_compensation`

核对日期：2026-08-06

## 1. 输入和输出

```text
/capture/lidar/points_raw
/capture/odometry/high_rate_raw
→ odometry_timestamp_adapter_node
→ /capture/odometry/high_rate
→ enu_cloud_transform_node
→ /capture/lidar/points_compensated_enu
```

输出 `frame_id` 为 `lidar_local_enu`，字段语义为 `x=East/local horizontal 1`、
`y=North/local horizontal 2`、`z=Up`。

## 2. 时间适配

厂商高频里程计同一数据包内可能使用相同时间戳。适配节点按默认 400 Hz 展开样本
时间，默认把包时间戳解释为第一个样本时刻。该处理不修改厂商驱动源码。

点的采集时刻为：

```text
t_i = cloud.header.stamp + offset_time_i
```

## 3. 逐点变换

```text
r_n,i = R_n<-b(t_i) r_l,i + p_n(t_i) - p_n(t_0)
```

姿态使用四元数 SLERP，位置使用线性插值。平移项只补偿同一扫描内相对位移，不把
累计里程计位置写入最终测距结果。

## 4. 当前假设

- 雷达坐标轴与里程计机体系方向一致；
- 雷达到里程计原点的杆臂平移为零；
- Up 方向来自厂商里程计姿态；
- 不使用 IMU 瞬时加速度再次估计重力；
- 点云和里程计时间偏移默认均为 0，需要实测标定。

## 5. 无效和降级

- 姿态覆盖不足的少量点写为 NaN；
- 有效姿态比例低于 0.75 时默认丢弃整帧；
- 帧起始位姿不可插值时可按配置退化为仅旋转补偿；
- 单帧平移超过 2.5 m 时拒绝；
- 点云尾部最多允许 15 ms 暂时缺少里程计覆盖；
- 队列有界，失败时默认不发布空点云。

## 6. 验证边界

当前实现具备 C++ 核心测试和节点级测试。正式精度结论仍需要已标定外参、时间偏移和
车辆动态数据，不应仅根据静止场景判断补偿精度。
