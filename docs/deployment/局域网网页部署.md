# RK3588 局域网 Web 部署

核对日期：2026-08-07


> 当前边界：任务创建、控制、回放和导出均已接入设备端链路。开始采集前要求雷达原始点云在线且 RTK 串口诊断正常；入口和出口 RTK 仅确认最近 2 s 内收到的有效 Fix，未确认时记录状态并继续已经开始的任务。记录器以50 Hz保存最近源帧保持序列，真实净空源帧另表保留。

## 架构

前端在构建阶段导出为静态文件。RK3588 运行时只启动一个 FastAPI/Uvicorn
服务，由同一个端口提供：

- `/`：前端静态界面；
- `/api/health`：Web 服务健康检查；
- `/api/v1/tasks`：创建和查询持久化任务；
- `/api/v1/tasks/batch`：多任务事务创建；
- `/api/v1/tasks/{task_id}`：单任务查询和逻辑删除；
- `/api/v1/tasks/delete-selected`：单事务逻辑删除所选任务；
- `/api/v1/tasks/purge-data`：维护接口，物理清理所选任务的本地目录并保留任务索引；
- `/api/v1/map/config`：浏览器读取 RK3588 统一配置的高德 JS API Key；
- `/_AMapService/*`：FastAPI 使用设备端安全密钥代理高德 Web 服务；
- `/api/v1/task-control/readiness`：任务控制桥、各控制 Service 以及雷达/RTK开始准入状态；
- `/api/v1/tasks/{task_id}/start`：开始任务并冻结参数；
- `/api/v1/tasks/{task_id}/pause`：暂停正式记录；
- `/api/v1/tasks/{task_id}/resume`：继续正式记录；
- `/api/v1/tasks/{task_id}/stop`：停止任务并完成记录文件；
- `/api/v1/tasks/{task_id}/measurements`：历史测量文件读取；
- `/api/v1/reports/clearance-summary/preview`：读取所选任务正式导出资格和汇总预览；
- `/api/v1/tasks/{task_id}/export-jobs/txt`：创建任务50 Hz明细TXT后台作业；
- `/api/v1/reports/clearance-summary/export-jobs`：创建所选任务PDF后台作业；
- `/api/v1/export-jobs/{job_id}`：读取或取消作业，完成后从`/download`下载；
- `/api/v1/tasks/{task_id}/exports/txt`：兼容旧客户端的同步TXT及异常分析JSON接口；
- `/api/v1/reports/clearance-summary`：汇总请求体中的 `task_ids` 生成 PDF；
- `/ws/v1/cloud-preview`：PCV1点云WebSocket；
- `/ws/v1/clearance`：单帧净空结果WebSocket；
- `/ws/v1/rtk`：RTK状态和fix快照WebSocket；
- `/ws/v1/system-status`：统一系统状态WebSocket。
- `/ws/v1/task-status`：设备端任务状态和执行阶段WebSocket。

浏览器不直接连接 ROS 2。任务创建、创建时间显示编号、历史查询、批量逻辑删除、维护用物理清理和报告选择由 FastAPI 与 SQLite 管理；单任务控制通过独立 ROS 桥调用 `task_manager` Service。高德 Key 通过采集首页“地图设置”写入 RK3588 的 `runtime/settings/device_settings.json`，浏览器不长期保存 `securityJsCode`。旧批次表只用于历史兼容。网络断开不会停止活动任务。

## 新机环境准备

目标机预装 Ubuntu 22.04 和 ROS 2 Humble 后，优先使用统一环境与双网口部署入口：

```bash
cd /path/to/capture_system
sudo bash scripts/deploy/install.sh \
  --variant development \
  --lidar-interface <雷达物理网口> \
  --direct-interface <维护物理网口>
```

该脚本只安装依赖、串口权限和双网口系统配置，不执行项目编译，也不启动任何 ROS 2 节点。详细回滚和清理方式见 [RK3588 双网口环境与网络部署](RK3588双网口环境与网络部署.md)。

环境配置成功后，项目自己的 Python、npm 和 ROS 2 构建依赖继续由统一构建脚本准备，不需要手工在多个目录重复安装。

## 构建前端

```bash
cd /path/to/capture_system
scripts/build/build.sh web
```

构建成功后必须存在：

```text
/path/to/capture_system/frontend/out/index.html
```

如果该文件不存在，FastAPI 会拒绝启动并明确报告静态构建缺失，避免设备提供
不完整页面。

## 手动运行

开发阶段推荐直接使用一键前台脚本：

```bash
cd /path/to/capture_system
scripts/operation/run_lan_preview.sh
```

该脚本会依次启动雷达驱动、点云预览节点、首版净空计算节点、RTK驱动、系统
监控、网页服务、`data_recorder`和`task_manager`，并等待开始、暂停、继续和停止四个核心任务控制 Service 就绪；恢复 Service 未就绪时仅告警。
按 `Ctrl+C` 会统一停止本次启动
的进程，不安装或启用任何开机自启服务。室内没有有效定位时，RTK节点仍保持运行；RTK驱动通过`/diagnostics`报告
串口事实，`system_monitor`将其与雷达、RK3588和实际数据存储状态统一发布到
`/capture/system/diagnostics`。

需要分别调试组件时，可先加载业务工作空间并启动点云预览节点：

```bash
source /opt/ros/humble/setup.bash
source /path/to/capture_system/ros2_ws/install/setup.bash
ros2 launch bringup cloud_preview.launch.py
```

单独调试首版净空计算节点：

```bash
ros2 launch bringup clearance_preview.launch.py
```

该入口启动高频里程计时间适配、逐点运动补偿和净空算法，输入最终为 `/capture/lidar/points_compensated_enu`。

单独调试RTK驱动：

```bash
ros2 launch rtk_driver rtk_driver.launch.py
```

单独调试设备端任务控制和记录：

```bash
ros2 launch bringup task_control.launch.py \
  data_root:=<project_root>/runtime
```

该 Launch 要求 `capture.db` 已经由 FastAPI 完成当前 schema version 7 迁移。正常一键启动脚本
会先等待FastAPI健康检查，再启动任务控制Launch。

雷达驱动由系统采集Launch或当前 `sensor_adapter` 入口启动。确认以下Topic存在：

```bash
ros2 topic info /capture/visualization/cloud_preview
```

再启动Web服务：

```bash
cd /path/to/capture_system
scripts/operation/run_web.sh
```

默认监听所有 IPv4 网卡的 TCP 8000 端口。在 RK3588 上查询地址：

```bash
ip -br address
```

假设有线地址为 `192.168.1.200`，同一网段电脑访问：

```text
http://192.168.1.200:8000/
```

健康检查：

```bash
curl http://192.168.1.200:8000/api/health
```

正常响应为：

```json
{"status":"ok"}
```

采集首页点云面板只保留三维视图和放大按钮，不再显示旧版帧数、FPS和frame底部状态栏。可在浏览器开发者工具或ROS 2 Topic中检查链路。

## 网络参数

参数文件是 `config/network/web.env`：

| 参数 | 单位/格式 | 默认值 | 合法范围 | 失效行为 |
| --- | --- | --- | --- | --- |
| `UVICORN_HOST` | IPv4 地址 | `0.0.0.0` | 本机有效监听地址 | 地址不可用时服务启动失败 |
| `UVICORN_PORT` | TCP 端口 | `8000` | `1`–`65535`，且未被占用 | 端口无效或被占用时服务启动失败 |
| `CAPTURE_STATIC_DIR` | 绝对目录 | `frontend/out` 的绝对路径 | 必须包含 `index.html` | 服务启动失败并报告缺失文件 |
| `CAPTURE_DATA_ROOT` | 绝对目录 | `<project_root>/runtime` | 运行用户可创建和写入 | 启动脚本拒绝启动，任务 API 不可用 |

`0.0.0.0` 表示同时监听有线和 Wi-Fi 网卡。它不是浏览器访问地址；浏览器必须
使用 RK3588 在相应局域网内的实际 IP。

Web启动脚本会先创建 `CAPTURE_DATA_ROOT/tasks` 并检查写权限，再依次加载ROS 2、厂商
驱动工作空间和业务工作空间，固定使用一个
Uvicorn worker，并关闭点云WebSocket压缩。`.venv`必须安装
`backend/requirements.txt` 中的NumPy，否则ROS消息类型无法载入，页面会显示
“ROS桥不可用”。

记录器参数位于`ros2_ws/src/data_recorder/config/data_recorder.yaml`。`sample_rate_hz`
标称采样率为50 Hz，正式写入由20 ms墙钟触发并明确保存最近源帧来源；约400 Hz IMU在
相邻结果之间累加求平均，事务批量为100条。相同高度或最低点不会被当作重复日志删除。


## 设备端 Wi-Fi 连接

正式前端侧栏提供 Wi-Fi 连接入口。浏览器只访问 FastAPI，实际扫描和连接由 RK3588 上的 NetworkManager 执行。连接成功后界面只显示 NetworkManager 当前确认的真实 SSID 名称，不显示模拟地址、接口名或信号状态。

板端前置条件：

```bash
command -v nmcli
nmcli general status
nmcli device status
nmcli general permissions
```

无线网卡必须由 NetworkManager 管理。`capture-web.service` 继续以安装时确定的普通用户运行，不提升为 root。项目同时提供 JavaScript `.rules` 与 Local Authority `.pkla` 模板，统一部署脚本根据主机实际 polkit authority 选择首选机制，并用 `nmcli general permissions` 验证实际权限。AIO-3588JQ 的 Firefly Ubuntu 22.04 实机使用 Local Authority `.pkla`。

当前 Wi-Fi 功能只要求三个 NetworkManager action：

```text
org.freedesktop.NetworkManager.wifi.scan
org.freedesktop.NetworkManager.settings.modify.system
org.freedesktop.NetworkManager.network-control
```

不默认授权 `org.freedesktop.NetworkManager.settings.modify.own`。`wifi.scan` 已实机确认用于后台主动扫描，`settings.modify.system` 已实机确认用于创建当前实现的 system-wide Wi-Fi profile。`network-control` 的授权已实机确认可变为 `yes`，真实 AP 切换需要在 SSH 或维护控制通道独立于 `wlan0` 时验收。

系统权限应通过环境部署安装：

```bash
sudo bash scripts/deploy/install.sh --variant customer
sudo bash scripts/deploy/verify_deployment.sh --configured-only
```

验证脚本要求实际运行用户的上述三个 action 全部为 `yes`。polkit 正常自动重载时不需要重启 NetworkManager，也不需要重启 polkit；只有部署脚本检测到自动重载后权限仍未生效时，才会单独重启 `polkit.service` 并复核。

可选 systemd 安装仍使用：

```bash
sudo bash scripts/deploy/install_systemd.sh
```

该脚本只安装 Web service，并检查 `install.sh` 已经配置好 NetworkManager 权限；它不单独写入 polkit，也不创建或递归修改 `<project_root>/runtime`。polkit 文件的安装和恢复统一由 `install.sh`、状态快照、`rollback.sh` 和 `clear_config.sh` 管理。

接口为：

```text
GET  /api/v1/network/wifi/status
GET  /api/v1/network/wifi/networks
POST /api/v1/network/wifi/rescan
POST /api/v1/network/wifi/connect
```

Wi-Fi 密码只在单次 HTTPS/HTTP 请求内进入 FastAPI，并通过权限为 `0600` 的临时 `passwd-file` 交给 `nmcli connection up`。临时文件在命令结束后删除。项目不会把密码写入 `capture.db`、任务事件、开发 MCAP、普通日志或浏览器存储。NetworkManager 是否持久保存连接凭据由其系统连接配置负责。

当前默认 Web 部署使用 HTTP。HTTP 不提供链路加密，因此同一网络中的被动监听者理论上可以观察浏览器提交的 Wi-Fi 密码。正式部署若存在非可信局域网，应在 Web 服务前增加 HTTPS 终止；本轮没有把 HTTP 描述成加密传输。

如果当前浏览器正通过要切换的 Wi-Fi 访问 RK3588，切换网络时连接可能中断，新网络的 DHCP 地址也可能变化。现场配置时优先通过有线网络访问设备。

## systemd开机自启

完整 Capture System 开机自启通过构建参数和独立应用步骤控制：

```bash
bash scripts/build/build.sh all --release --variant customer --autostart on
sudo bash scripts/deploy/apply_autostart.sh
```

构建只记录 `CAPTURE_AUTOSTART_DESIRED`，不会调用 sudo 或修改 systemd。`apply_autostart.sh` 才会安装并 enable `capture-system.service`，并 disable 与其冲突的 Web-only `capture-web.service`。默认不立即启动或停止当前业务进程。

关闭下次开机自启：

```bash
bash scripts/build/build.sh all --release --variant customer --autostart off
sudo bash scripts/deploy/apply_autostart.sh
```

自启实例运行时需要修改源码和重新编译，先停止当前实例：

```bash
sudo bash scripts/operation/stop_capture_system.sh
```

该命令不执行 disable。编译完成后可立即恢复：

```bash
sudo systemctl start capture-system.service
```

查看状态和日志：

```bash
systemctl status capture-system.service
journalctl -u capture-system.service -f
bash scripts/deploy/status.sh
sudo bash scripts/deploy/verify_deployment.sh --autostart-only
```

设备重启并由完整服务运行后可执行：

```bash
sudo bash scripts/deploy/verify_deployment.sh --expect-autostart
```

如果只需要 Web-only 服务，仍可使用 `sudo bash scripts/deploy/install_systemd.sh`。该模式与完整 `capture-system.service` 互斥。

## 项目自定位与运行目录

默认情况下不需要预先知道项目绝对路径。`scripts/operation/run_web.sh` 和 `scripts/operation/run_lan_preview.sh` 会根据脚本自身位置计算项目根目录，并设置：

```text
CAPTURE_PROJECT_ROOT=<当前项目目录>
CAPTURE_DATA_ROOT=<当前项目目录>/runtime
```

默认运行目录结构为：

```text
runtime/
├── capture.db
├── tasks/
├── reports/
├── dev-tests/
└── settings/
    └── device_settings.json
```

项目移动到其他目录后，上述默认路径会随项目位置改变。不要在升级脚本中删除 `runtime/`。发布归档不应包含现场 `runtime/` 数据。

systemd 服务不要直接复制仓库中的模板文件。进入当前项目根目录后执行：

```bash
sudo bash scripts/deploy/install_systemd.sh
```

安装脚本会把当前项目真实路径、当前运行用户和 `<project_root>/runtime` 写入 `/etc/systemd/system/capture-web.service`。

## 高德地图设备配置

高德 Web JS API Key 和 `securityJsCode` 通过采集首页的“地图设置”维护。保存后配置写入：

```text
<project_root>/runtime/settings/device_settings.json
```

文件权限为 `0600`。安全密钥仅供 FastAPI 地图代理使用，读取配置接口不会把安全密钥返回浏览器。`config/network/web.env` 中的高德环境变量只作为首次迁移兼容项，正常交付后无需通过 SSH 修改该文件。
