# 采集首页操作说明

适用版本：`0.2.0`

核对日期：2026-08-09

本文说明当前浏览器界面可见功能。任务创建、开始、暂停、继续、停止、回放和导出
均通过FastAPI接入设备端。浏览器不直接访问ROS 2。

## 1. 打开页面

完成设备构建并运行：

```bash
cd /path/to/capture_system
scripts/operation/run_lan_preview.sh
```

在同一局域网电脑中打开脚本打印的地址。

## 2. 顶部状态区

- 系统状态：根据四类设备诊断显示检查中、正常或告警；
- 净空高度：顶部摘要显示实时 `lidar_to_top_m` 加雷达安装高度，单位 m；正式任务记录中的 `clearance_height_m` 使用同一定义；
- RTK定位：原始RTK的WGS84纬度、经度和高度，以及卫星数、HDOP/PDOP；
- 当前净空低于高度下限阈值或超过高度上限阈值时数值变为红色，检测恢复正常后使用默认颜色；
- 雷达、RTK、主控板和数据存储：绿色灯表示有明确连接或有效诊断证据，红色灯
  表示未连接、数据超时或证据不足。

没有接入雷达或 RTK 时，对应状态灯应为红色。主控板和存储是本机资源，即使外部
设备没有接入，也可能保持绿色。

## 3. 点云和地图

点云区只提供三维视图。鼠标可旋转、平移和缩放。右上角按钮进入放大显示，按
`Esc`、点击背景或再次点击按钮退出。

地图只在RTK有效时使用原始坐标绘制蓝色轨迹。RTK无效或地图断线时保留最后有效位置，
但不新增轨迹，不使用ODIN位置或姿态推算坐标。轨迹不会随时间裁剪，切换到数据回放、
报告导出或测试页面时仍持续接收有效RTK，返回首页后完整显示；当前位置显示为蓝色圆点。

## 4. 原始 RTK

顶部RTK定位栏显示原始RTK纬度、经度、高度、卫星数和HDOP/PDOP。融合定位状态卡已
删除，原任务状态区域扩展到释放的空间。页面不显示入口或出口坐标；原始RTK数值仅反映
最新快照，不表示已通过稳定性验收。

## 5. 创建任务

点击“创建任务”打开录入窗口，每次只填写一个任务：

- 隧道编号；
- 隧道名称；
- 作业车道，可选上行左车道、上行右车道、下行左车道、下行右车道；
- 高度下限阈值，单位 m，允许为 `0 m`；
- 高度上限阈值，单位 m，默认 `20 m`，必须不小于高度下限阈值。

点击“保存并关闭”后结束录入；点击“保存并继续创建”时，前一个任务必须先由 FastAPI 成功写入数据库并返回正式编号，页面才会清空表单进入下一项。FastAPI 为每个任务生成稳定 UUID 和创建时间显示编号，例如 `20260807_145601`。同一秒连续创建多个任务时，后续任务使用 `_02`、`_03` 后缀。浏览器不自行生成正式编号。旧批量创建接口只保留兼容，不参与当前页面流程。

删除历史任务不会影响后续任务编号。刷新页面、重启 FastAPI 或重新启动设备后，任务仍从 SQLite 中读取。同一隧道编号允许创建多次检测任务。

## 6. 作业参数

任务控制卡片保留四个运行参数，并在笔记本屏幕上按两列两行显示：

- 雷达安装高度，单位 m；
- 作业车道，显示当前任务的上/下行方向和左/右车道；
- 高度下限阈值，单位 m；
- 高度上限阈值，单位 m。

每个任务在创建时保存独立的计划作业车道、计划高度下限阈值和计划高度上限阈值。选择待执行任务后，任务控制卡片自动加载该任务计划值。现场情况变化时，可以在点击“开始采集”前修改这些参数；开始时设备端把卡片当前值冻结为实际执行参数，正式记录和报告均使用实际执行值。两个阈值都允许 `0 m`，范围均为 `[0, 20] m`，且高度下限阈值不能大于高度上限阈值。采集中、暂停和控制过渡阶段禁止再修改这些参数。

雷达安装高度不属于任务创建字段，仍在任务控制卡片中设置。每次前端系统启动时雷达安装高度默认 `0 m`，高度下限阈值的新任务默认 `0 m`，两项均允许为 `0 m`。净空算法输出与实时曲线中的 `lidar_to_top_m` 不加入雷达安装高度；正式记录同时保存原始 `lidar_to_top_m`，并把 `clearance_height_m` 保存为 `lidar_to_top_m + 雷达安装高度`。

## 7. 任务切换和队列

当前任务区显示创建时间编号、隧道名称、实际或计划作业车道和状态。连续创建多个任务时，默认从最早创建且尚未执行的任务开始，并在每个任务正常停止后按创建顺序选择下一项，不自动开始。点击“切换任务”可以人工改变选择。采集中或暂停时不允许切换。

待测任务区只显示其他待执行任务，并与作业参数、当前任务共用卡片中部滚动区域。
底部控制按钮固定在卡片底部，不会覆盖队列。

## 8. 控制按钮

- 开始采集：单击后立即调用设备端任务状态机，不显示确认弹窗。流程依次显示雷达
  初始化、入口RTK记录、记录文件创建和正式记录；
- 暂停：停止正式测量样本写入，实时点云、净空和RTK展示继续；
- 继续：关闭暂停区间并恢复正式样本写入；
- 停止：单击后立即固定停止时间，不显示确认弹窗。自动记录出口RTK快照，完成数据库
  收尾后显示已停止，并按创建时间自动选择下一项待执行任务。系统不会自动开始下一任务。

开始采集要求雷达和 RTK 均已上线。雷达上线以原始点云持续收到新帧为准，RTK 上线以串口诊断正常为准；任一设备未上线时开始按钮保持不可用。任务开始后，入口 RTK 只有在最近 2 s 内实际收到有效 Fix 时才确认坐标；没有 Fix、Fix 无效或最后 Fix 已超时都会显示“入口RTK坐标未确认”并继续记录。出口 RTK 使用相同规则，未确认时仍完成停止，报告对应坐标保持空值。

任务控制通过`/ws/v1/task-status`更新。浏览器刷新或断线不会停止设备端任务，重新打开
页面后会恢复持久状态。准备、暂停、继续或停止阶段超时后，设备端会自动恢复到安全状态。
若仍显示活动任务卡住，可使用“停止”或“恢复控制”，不需要重新启动系统。

## 9. 数据回放和报告导出

数据回放页面直接列出全部任务，并按创建日期分组。日期分组和同日任务均按创建时间正序显示，与任务创建顺序一致。存在测量文件时，页面先读取任务开头固定样本段并立即显示，完整统计随后异步读取；放大或平移后自动读取当前区间。已经加载的曲线窗口在本次页面会话中保留，回拖到已缓存且分辨率足够的区间不会重复请求，放大到更细分辨率时再补读。显示降采样保留局部最低值、最高值和无效断点，正式数据库保存50 Hz最近源帧保持序列并保留来源字段。曲线纵向范围使用 Y＋、Y－和复位控制。没有测量文件时保持空状态。

数据回放中的删除采用逻辑删除，只把任务从普通列表中移除。用户可以逐项勾选、按日期选择，或对当前搜索和筛选结果执行“全选”，然后点击“删除所选任务”。采集中和已暂停任务不能勾选删除。批量删除由后端单个事务完成，任一任务不满足条件时整批不提交。普通客户界面不再提供物理清理入口；需要释放设备存储空间时由维护人员使用后端 `/api/v1/tasks/purge-data` 接口。

TXT 面向当前任务，以实际收到的每帧IMU为一行，固定输出用户定义的38列原始数据；未记录和空数据写`0`，列间使用4个ASCII空格。原有PDF面向报告页中勾选的一个或多个任务，表格保留任务、隧道、车道、原始单帧最低值、时间和入口/出口RTK，不再显示建议最低可信净空与可信度。导出在后台运行，可显示进度、取消，并在刷新页面后继续跟踪。原始SQLite不被报告分析修改。

如需大模型辅助分析，在报告页选择一个正式可导出的当前任务，编辑DeepSeek API地址、API Key、模型和“大模型Skill”，然后点击“AI报告生成”。配置修改后自动保存到RK3588的runtime设置文件，换电脑访问同一设备时可继续使用。每次点击都会开启一次新的DeepSeek请求，不延续前一次上下文。大模型Skill用于调整分析规则，固定JSON输出字段由后端自动附加，无需用户在Skill中重复填写。RK3588只读流式扫描当前任务数据库，在本地计算源帧统计、最低20帧、3组候选的前后各5帧证据和IMU/RTK质量；即使`measurements.db`较大，也只发送固定大小的审计包，不上传数据库全表。当前支持数据库与WAL合计最大2 GiB，超过时明确提示。生成的PDF先列出固定任务表格，随后只给出“报告分析结果”和“数据质量分析”。生成期间界面以跳动的“大模型thinking...”文字提示，不显示百分比进度。

## 10. 常见问题

### 设备未接入但状态灯曾显示绿色

当前版本已改为显式连接证据，并在系统诊断快照超过 5 秒时清空旧状态。若仍出现，
检查浏览器缓存是否加载了旧静态文件，并确认 FastAPI 实际托管的是最新
`frontend/out/`。

### RTK定位经纬高显示 `--`

可能原因包括RTK WebSocket未连接、没有fix、RMC为`V`或原始RTK字段为空。页面不会用
融合定位或ODIN位姿补造坐标。

### 开始采集按钮不可用

检查当前任务、雷达安装高度、高度下限阈值、高度上限阈值、雷达与 RTK 上线状态以及任务控制 Service。雷达没有持续原始点云、RTK 串口未连接或系统诊断超时时都会禁止开始。若设备已上线但仍提示任务控制不可用，再检查 `task_manager` 和 `data_recorder`。

### 入口或出口RTK显示坐标未确认

该状态表示按钮操作时没有最近 2 s 内收到的有效 RTK Fix，原因可能是没有 Fix、Fix 无效或数据已超时。任务不会因此暂停或等待。检查 RTK 串口、定位状态和数据是否持续更新，后续任务仍可继续执行。报告中缺失端点坐标保持空值。
