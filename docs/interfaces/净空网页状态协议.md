# 净空网页状态协议

核对日期：2026-08-24

## 1. 地址和来源

同源 WebSocket：

```text
/ws/v1/clearance
```

ROS 2 来源：

```text
/capture/clearance/result
```

每个客户端只保留最新一帧，最高发送 10 Hz。超过 1 秒没有新结果时，流状态变为
`degraded`。

## 2. 快照

```json
{
  "type": "clearance_snapshot",
  "sequence": 12,
  "emitted_at_ns": 1785740000000000000,
  "stamp_ns": 185000000000,
  "frame_id": "device0/odom",
  "valid": true,
  "lidar_to_top_m": 3.56,
  "ransac_plane_count": 0,
  "candidate_count": 1,
  "selected_inlier_count": 57,
  "selected_area_m2": null,
  "selected_tilt_deg": null,
  "residual_median_m": null,
  "residual_p95_m": null,
  "minimum_position_east_m": null,
  "minimum_position_north_m": null,
  "minimum_position_up_m": null,
  "valid_point_ratio": 0.83,
  "invalid_reason": "",
  "processing_time_ms": 46.2
}
```

ROS 2 中非有限浮点数转换为 JSON `null`。无效帧必须同时保留 `valid=false` 和 `invalid_reason`。

当前原始点簇算法令 `ransac_plane_count=0`，有效帧 `candidate_count=1`，并用
`selected_inlier_count` 表示最低可信簇点数。面积、倾角、残差和 ENU 最低位置字段置为 JSON
`null`，仅为旧接口兼容保留。真实代表点本体系坐标只在设备端诊断 Topic 中提供。

## 3. 测量语义

`lidar_to_top_m` 是原始雷达本体系最低可信簇的 X 中位距离。WebSocket 字段本身不加入雷达安装高度。采集首页和记录器使用 `lidar_to_top_m + 雷达安装高度` 得到最终高度；上下限边界包含在正常范围内。正式任务记录同时保留原始值和安装高度修正后的 `clearance_height_m`。

## 4. 页面行为

- 有效且非空且雷达安装高度有效时，顶部数值显示 `lidar_to_top_m + 雷达安装高度`；
- 无效、超时或断线时显示 `--`；
- 最近 120 帧曲线在无效帧处断开；
- 不沿用上一帧值冒充当前值；
- 当前有效净空低于任务高度下限阈值或超过高度上限阈值时数值显示红色，恢复正常后立即使用默认颜色；
- 不在浏览器累计任务最小净空。
