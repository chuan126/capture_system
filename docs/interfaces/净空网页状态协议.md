# 净空网页状态协议

核对日期：2026-08-09

## 1. 地址和来源

同源 WebSocket：

```text
/ws/v1/clearance
```

ROS 2 来源：

```text
/capture/clearance/result
```

每个客户端只保留最新一帧，最高发送 10 Hz。超过 1 秒没有新结果时，流状态变为
`degraded`。

## 2. 快照

```json
{
  "type": "clearance_snapshot",
  "sequence": 12,
  "emitted_at_ns": 1785740000000000000,
  "stamp_ns": 185000000000,
  "frame_id": "lidar_local_enu",
  "valid": true,
  "lidar_to_top_m": 3.56,
  "candidate_count": 2,
  "selected_inlier_count": 842,
  "selected_area_m2": 1.25,
  "selected_tilt_deg": 2.1,
  "residual_median_m": 0.011,
  "residual_p95_m": 0.032,
  "minimum_position_east_m": 0.12,
  "minimum_position_north_m": -0.35,
  "minimum_position_up_m": 3.56,
  "valid_point_ratio": 0.83,
  "invalid_reason": "",
  "processing_time_ms": 46.2
}
```

ROS 2 中非有限浮点数转换为 JSON `null`。无效帧必须同时保留 `valid=false` 和 `invalid_reason`。

`candidate_count` 是通过质量检查的连通区域数。它与 `ransac.max_candidate_planes` 的 RANSAC 模型提取上限不是同一指标，一个模型可对应多个连通区域。`selected_area_m2` 为兼容字段名，实际语义是选中区域的水平投影网格覆盖面积，不是几何平面表面积。

## 3. 测量语义

`lidar_to_top_m` 是雷达原点到最低合格近水平顶面的竖直距离。WebSocket 字段本身不加入雷达安装高度。采集首页顶部摘要与高度阈值判定使用 `lidar_to_top_m + 雷达安装高度`；最近 120 帧实时曲线继续显示原始 `lidar_to_top_m`。正式任务记录同时保留原始 `lidar_to_top_m`，并把 `clearance_height_m` 保存为安装高度修正后的净空高度，算法输出本身不修改。

## 4. 页面行为

- 有效且非空且雷达安装高度有效时，顶部数值显示 `lidar_to_top_m + 雷达安装高度`；
- 无效、超时或断线时显示 `--`；
- 最近 120 帧曲线在无效帧处断开；
- 不沿用上一帧值冒充当前值；
- 当前有效净空低于任务高度阈值时数值显示红色，恢复正常后立即使用默认颜色；
- 不在浏览器累计任务最小净空。
