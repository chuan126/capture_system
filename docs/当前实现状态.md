## 4. 采集首页当前结构

顶部状态区包含系统总状态、实时显示净空高度、原始RTK纬度/经度/高度及卫星与DOP信息，以及雷达、RTK、主控板和数据存储四项状态。实时显示净空高度按 `lidar_to_top_m + 雷达安装高度` 计算；低于任务高度下限阈值或超过高度上限阈值时当前数值变为红色，正常时保持默认颜色。算法输出和实时曲线继续使用原始 `lidar_to_top_m`，正式记录的 `clearance_height_m` 保存安装高度修正后的高度。

主体区域包含：

- 仅保留三维交互视图的点云实时预览，支持放大显示；
- 高德实时地图，RTK有效时绘制蓝色RTK轨迹，RTK无效且航位推算有效时绘制浅黄色融合轨迹并显示“当前为融合定位结果”；支持放大显示，Key由RK3588统一配置，安全密钥仅由FastAPI代理使用；
- 最近 120 帧有效高度和无效帧断点曲线；
- 融合定位栏，显示航位推算纬度/经度/高度、ODIN四元数换算的俯仰/横滚，以及与地图小车一致的实际车向；
- 任务控制卡片。

任务控制卡片当前行为：

- 创建窗口每次录入一条任务，填写隧道编号、隧道名称、作业车道、高度下限阈值和高度上限阈值；作业车道提供上行左、上行右、下行左、下行右四种组合；
- 前端显示任务编号由创建时间生成，例如 `20260807_145601`，同秒多任务追加 `_02`、`_03`；
- 内部状态和文件目录始终使用稳定 UUID，删除历史任务不会导致编号重排；
- 每个任务在创建时保存独立的计划行驶方向、左右车道、高度下限阈值和高度上限阈值。选中待执行任务后，任务控制卡片加载该任务计划值；开始前可现场覆盖作业车道和两个阈值，点击开始后由设备端冻结实际执行值。雷达安装高度仍是当前设备运行参数；雷达安装高度和高度下限阈值允许为 0 m，高度上限阈值默认 20 m，前端系统启动时雷达安装高度默认 0 m；
- 当前任务区显示自动任务编号、隧道编号、隧道名称、车道和文字状态；
- 作业参数、当前任务和待测任务由任务控制卡片中部统一滚动；
- 底部开始、暂停和停止区固定，不覆盖任务列表；
- 采集中和暂停时锁定已经冻结的实际执行参数和任务切换；
- 页面刷新和 FastAPI 重启后会从设备端任务数据库恢复任务列表；
- 开始、暂停、继续和停止调用 FastAPI，再由任务控制桥调用 ROS 2 Service；开始和停止没有确认弹窗；
- 控制状态由 `/ws/v1/task-status` 和任务数据库恢复，浏览器不自行确认操作成功；
- 开始采集前要求雷达原始点云在线且 RTK 串口诊断正常，任一设备未上线时禁止开始；
- 入口和出口RTK没有最近 2 s 内收到的有效 Fix 时显示“坐标未确认”，流程继续执行；
- 停止成功后按创建时间自动选择下一项待执行任务；
- 过渡状态具有超时看门狗、停止取消和人工恢复入口，活动槽异常无需重启系统。


## 5. 数据回放和报告界面状态

数据回放与报告导出页面共享 FastAPI 返回的设备端任务列表和浏览器当前选择，不再暴露作业批次。任务停止后，采集首页可直接进入相同任务的回放或报告页面。

数据回放页面按创建日期分组任务，包含当前任务净空高度曲线、测量统计、隧道端点和数据质量。长任务首屏不再扫描整条曲线，而是通过 `series-prefix` 按 `sample_index` 固定读取任务开头 2000 条样本并立即显示；完整统计随后异步读取。用户拖拽或缩放到其他时间位置后，再通过按源时间戳窗口的 `series` 接口读取当前视图，最多返回 6000 个显示点。已经读取的显示样本按 `sample_index` 合并保留在当前任务内存缓存中，并记录已加载时间区间和显示分辨率；回到分辨率足够的缓存区间不重复请求，放大到更细分辨率时才补读。大窗口降采样保留局部最低值、最高值和无效断点，“回到开头”恢复首段窗口，不主动加载完整任务曲线。正式记录和导出使用完整真实测量序列。回放页支持逐项、按日期以及当前筛选结果全选后批量逻辑删除，采集中和已暂停任务不可删除。物理清理接口继续存在，但已从客户数据回放页面移除。

采集首页点云预览继续使用 `/capture/lidar/points_compensated_enu` 的独立显示旁路。`cloud_visualization` 在有网页消费者时才生成预览，先剔除非有限点和明确 `(0,0,0)` 占位点；有效点不超过 10000 时全部发送，超过后按 5 cm 体素优先保留空间代表点并补足或限点。该处理不修改运动补偿输出或 `clearance_engine` 输入。development 测试页为双列单页，左列为核心配置和离线算法调试，右列为净空算法、RTK与融合定位和原始点云样本；净空卡显示真实 `ransac_plane_count`。原始点云样本只提供保存、停止、删除，并在同一 MCAP 中附带 `/capture/odometry/high_rate_raw` 以支持隔离的完整离线时间适配、运动补偿和净空算法重放。离线停止后进度冻结，算法节点提前退出会立即失败并附带日志摘要；无效帧不会清除上一有效雷达到顶距离，同时显示当前帧无效原因和 ENU diagnostics。页面复用正式 RTK/净空 WebSocket，不调用 `/api/dev/overview`，普通打开测试页不会续租 development 高频 telemetry。

设备端 `data_recorder` 为正式任务生成 `measurements.db`。当前新记录使用 measurement schema v12。记录器以50 Hz写入最近净空源帧保持序列，同时保存源时间、源序号、源年龄、重复序号、逐样本RTK纬经高和质量、端点快照、暂停区间及任务事件，并把每个20 ms区间内约400 Hz IMU累加求平均。俯仰/横滚来自车辆安装矩阵；TXT方位与地图车向统一使用定位节点的融合绝对方位。ODIN原始位置与四元数均保存。无效算法结果按无效样本记录，不沿用上一有效净空值。

报告页面已接入50 Hz测量明细TXT和隧道净空检测汇总PDF。TXT固定48列并同时生成异常分析JSON。TXT/PDF使用持久化异步作业，支持进度、取消和刷新恢复；正式采集活动时保持排队。最低净空采用可追溯的距离域事件分析，只排除`HIGH_CONFIDENCE_OUTLIER`，待复核和受保护真实结构仍保守计入。界面测试数据不会进入正式文件。
