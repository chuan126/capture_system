# 原始本体系净空重构验收（2026-08-24）

## 1. 结论

本轮已完成“原始雷达本体系最低可信点簇”工程重构，并按后续授权删除融合定位算法、
对应测试和前端融合状态卡。正式净空链路不再依赖 IMU、里程计、四元数、融合定位、
姿态补偿、运动补偿或 ENU 点云；网页点云预览现已改为独立原始 X-Y-Z 旁路。

当前结论是：**工程实现和固定数据回放通过，可以进入现场标定；尚未完成已知真值和高速
实车验收，不能据此宣称测量精度达标或可直接投产。**

## 2. 实施边界

- 正式输入改为 `/capture/lidar/points_raw`，输出继续使用 `/capture/clearance/result`。
- ROI 为闭区间 `min_x≤X≤max_x` 且 `Y²+Z²≤R²` 的圆柱区域。
- 按 X 高度带搜索，在 YZ 网格做八邻域连通；点数、占用格数和空间跨度同时满足才接受。
- 高度取最低可信簇 X 中位数；代表点和分类索引均来自真实原始点，不生成虚构坐标。
- 核心使用标准 C++ 直接解析固定 PointCloud2 布局并保留原始线性索引，未为形式上使用 PCL
  增加一次点云容器复制；排序、滑窗和网格连通均在有界帧内数据上完成。
- 无效帧发布 NaN 和当前原因，不复用上一帧结果。
- Plane/Surface 正式实现、死代码和相应测试已删除；旧结果字段只保留接口兼容并置零或 NaN。
- 融合航位推算、点云旋转和运动补偿核心、节点、配置及测试已删除。历史 SQLite、Web 和消息
  兼容字段保留为空值，原始 RTK、IMU 和 ODIN 数据记录保留。
- 前端融合状态卡已删除，任务状态卡以单行弹性布局填满原侧栏区域；地图只显示原始 RTK。

## 3. 坐标、字段和默认参数

固定 MCAP 的原始点云为 `frame_id=device0/odom`，每帧 49,152 点，`point_step=18`；
X/Y/Z 为 offsets 0/4/8 的 FLOAT32，intensity/confidence 为 offsets 12/13 的 UINT8，
`offset_time` 为 offset 14 的 FLOAT32。安装矩阵、现有测试和样本数值支持雷达 `+X` 为高度轴，
但样本没有物理真值，因此这只是工程证据，不替代现场轴向确认。

| 参数 | 默认值 | 说明 |
| --- | ---: | --- |
| `raw_cluster.min_detection_x_m` | 0.2 m | 当前现场近距离标靶配置；必须同时排除车辆与安装结构 |
| `raw_cluster.max_detection_x_m` | 10.0 m | 最大检测高度 |
| `raw_cluster.detection_radius_m` | 1.0 m | 围绕 X 轴的圆柱半径 |
| `raw_cluster.support_height_band_m` | 0.05 m | 候选高度带 |
| `raw_cluster.min_support_points` | 5 | 连续簇最少点数 |
| `raw_cluster.spatial_grid_size_m` | 0.10 m | YZ 网格边长 |
| `raw_cluster.min_occupied_cells` | 3 | 最少占用格数 |
| `raw_cluster.min_spatial_span_m` | 0.10 m | Y/Z 至少一轴的最小跨度 |

以 `min_detection_x_m=0.2` 回放时，六个半径均锁定 0.225–0.227 m、约 201–205 点的
近场簇。这不能在无标签样本上断言为误检，但说明当前近距离配置必须配合车辆本体与安装结构
遮挡标定，不能只依赖 X 下限过滤。

## 4. 三色预览

预览订阅 `/capture/lidar/points_raw`，保持原始 X-Y-Z 且不参与净空计算。预览节点仅以
“精确时间戳＋原始线性索引”关联原始算法诊断；诊断缺失、
错帧或分类未知时整帧安全退蓝，不沿用旧分类。

- 蓝色 `#3B82F6`：所有正常预览点；
- 绿色 `#22C55E`：当前算法 ROI；
- 红色 `#FF4D4F`：当前帧检测到的有效最低可信簇，始终标红。

点云颜色不依赖任务状态、安装高度或高度阈值；冗余的预览任务阈值消息已删除。前端和 FastAPI
不反算分类。分类诊断使用 best-effort 有界队列，丢帧只影响颜色，
不反压正式计算；同帧诊断晚到时重新发布该帧的正确颜色。

ROS 预览点云使用 XYZ＋`classification`（`point_step=16`）。后端严格校验字段类型、偏移、
大小端、height、row_step 和负载后封装为 PCV2，同时保留 PCV1 兼容。降采样优先级为
红＞绿＞蓝，浏览器只按设备分类渲染，不包含 ROI 或阈值算法。

## 6. 预览旁路基准

固定 `algorithm_10hz.mcap` 共 125 帧，每帧输入 49,152 点、输出上限 10,000 点：

| 项目 | mean/P95/max (ms) |
| --- | ---: |
| 分类关联 | 0.011 / 0.021 / 0.064 |
| 降采样与 PCV2 转换 | 48.94 / 66.53 / 76.96 |
| 旁路总耗时 | 48.95 / 66.54 / 76.99 |

该 MCAP 不含同时间戳原始分类诊断，因此 125 帧均按设计退化为全蓝；它只验证全蓝回退和
转换性能，不是匹配态三色性能证据。三色语义、有效最低簇始终标红、错帧退蓝和红点优先保留由单元
测试与节点测试覆盖。
