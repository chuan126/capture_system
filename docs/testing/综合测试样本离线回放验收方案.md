# 综合测试样本离线回放验收方案

更新日期：2026-08-24

## 1. 验收目标

验证测试界面保存的 MCAP 能通过隔离链路重新执行原始雷达本体系最低可信点簇算法。
离线回放只使用 `/capture/lidar/points_raw`，不等待或播放 IMU、里程计，不进行旋转、平移或
运动补偿，也不能把录制时的在线净空结果当作新结果。

## 2. 样本完整性检查

每个待验收样本目录至少包含：

```text
raw-cloud_YYYYMMDD_HHMMSS_xxxxxx/  # 单次综合测试样本目录
├── capture_manifest.json          # 文件、Topic、消息数和起止时间清单
├── parameter_snapshot.yaml        # 录制时算法参数快照
├── pointcloud_10hz.mcap           # 原始逐点点云，离线算法唯一必需输入
├── radar_state_400hz.mcap         # 原始IMU和里程计，仅供独立诊断
├── rtk_10hz.mcap                  # RTK数据，仅供独立诊断
├── algorithm_10hz.mcap            # 在线净空和索引诊断，仅用于对照
└── events_diagnostics.mcap        # 事件和诊断数据
```

开始回放前确认：

- `capture_manifest.json` 的 `finalized` 为 `true`；
- `pointcloud_10hz` 中 `/capture/lidar/points_raw` 消息数大于 0；
- 参数快照存在；若快照不完整，界面必须列出回退参数，不能静默隐藏；
- 旧单文件样本只要包含原始点云也应标记为可回放。

## 3. 功能验收步骤

1. 确认正式采集任务和综合测试录制均未运行。
2. 在测试界面选择一个已完成样本并启动离线检测。
3. 确认离线链路只启动一个 `clearance_engine_node` 和原始点云播放器。
4. 确认使用 `/capture/dev/offline/...` 隔离命名空间，正式 Topic 不收到回灌数据。
5. 检查运行参数快照包含 X 检测上下限、圆柱半径、高度带和空间支持参数。
6. 记录处理帧、有效帧、无效帧、最低/均值/最高距离、最低簇点数和处理耗时。
7. 对静止样本、车辆动态样本和手动停止产生的短样本重复检查。

## 4. 通过标准

| 项目 | 通过标准 |
| --- | --- |
| 输入完整性 | 原始点云消息数大于 0；IMU或里程计缺失不阻塞回放 |
| 算法配置 | 运行快照来自唯一的 `clearance_engine.yaml`，回退键明确列出 |
| 结果链路 | `processed_frames > 0`，状态为 `completed`，`last_error` 为空 |
| 处理覆盖 | `processed_frames / 原始点云帧数 >= 95%`；少量丢帧必须有计数 |
| 数值有效性 | 有顶面场景至少存在 1 帧有效结果，统计值均为有限数 |
| 失败可诊断性 | 无结果时错误包含净空节点或播放器日志末尾 |
| 隔离性 | 不写正式任务数据库，不改变正式任务状态，不回灌在线算法结果 |
| 原始坐标 | 结果和预览都不经过姿态旋转、坐标平移或运动补偿 |

## 5. 固定样本结果边界

2026-08-24 在 RK3588 上对 `raw-cloud_20260823_160031_ba50d8` 的 117 帧原始点云完成
六档半径回放，每档均收到 117/117 帧结果。该样本没有已知高度真值，只能验证确定性、参数
响应和处理性能，不能证明测量精度。详细数据见
[原始本体系净空重构验收](原始本体系净空重构验收_2026-08-24.md)。

## 6. 发布前自动化检查

```bash
PYTHONPATH=. PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 .venv/bin/pytest -q \
  backend/tests/test_dev_offline_replay.py \
  backend/tests/test_dev_recording_manager.py
```

自动化测试至少覆盖：隔离 Topic、raw-only 播放器命令、无里程计样本可回放、算法节点提前
退出、无结果错误和停止后进度冻结。自动化测试通过不能替代真实 MCAP 回放与现场真值测试。
