# 综合测试样本离线回放验收方案

更新日期：2026-08-23

## 1. 验收目标

验证测试界面保存的分频 MCAP 能通过隔离链路完成：原始高频里程计时间展开、位姿缓存、原始点云运动补偿、仅平面净空检测和网页结果统计。验收不能用录制文件中已有的补偿点云或在线净空结果代替重新计算结果。

## 2. 本次故障与修复判据

故障样本 `raw-cloud_20260823_160031_ba50d8` 包含 117 帧原始点云、4904 条原始高频里程计，并含 125 条录制时在线净空结果，排除了样本为空。

旧离线编排同时启动 400 Hz 状态播放器和 10 Hz 点云播放器。两个命令相同的 `-d 1.0` 只会让二者同时延迟，不能预填充位姿缓存。RK3588 日志显示点云尾部姿态持续落后约 0.42 至 0.46 秒，超过正式算法的 50 ms 等待门限，因此全部点云被丢弃。

修复后必须由编排层先读取首帧点云的 Header 与最大 `offset_time`，启动高频里程计播放器，并监听适配后的位姿时间戳；只有位姿真实覆盖首帧结束时间后才能启动点云播放器。两路分频文件以相同 0.5× 速率回放，离线位姿缓存为 5 秒，以吸收 RK3588 满载时的调度差异。不得用固定等待秒数猜测就绪状态，也不得通过放宽 `max_cloud_wait_s`、降低位姿覆盖率或回灌在线算法结果来使测试通过。

## 3. 样本完整性检查

每个待验收样本目录至少包含：

```text
raw-cloud_YYYYMMDD_HHMMSS_xxxxxx/  # 单次综合测试样本目录
├── capture_manifest.json          # 文件、Topic、消息数和起止时间清单
├── parameter_snapshot.yaml        # 录制时算法参数快照
├── pointcloud_10hz.mcap           # 原始逐点点云
├── radar_state_400hz.mcap         # IMU、原始及适配后里程计和四元数
├── rtk_10hz.mcap                  # RTK数据
├── algorithm_10hz.mcap            # 在线算法输出，仅用于对照
└── events_diagnostics.mcap        # 事件和诊断数据
```

开始回放前确认：

- `capture_manifest.json` 的 `finalized` 为 `true`；
- `pointcloud_10hz` 中 `/capture/lidar/points_raw` 消息数大于 0；
- `radar_state_400hz` 中 `/capture/odometry/high_rate_raw` 消息数大于 0；
- 参数快照存在；若快照不完整，界面必须列出回退参数，不能静默隐藏。

## 4. 功能验收步骤

1. 确认正式采集任务和综合测试录制均未运行。
2. 在测试界面选择一个已完成的综合测试样本并启动离线检测。
3. 确认界面先进入“启动/运行”，最终进入“完成”，不得出现“未收到净空结果”。
4. 检查离线 Topic 使用 `/capture/dev/offline/...` 隔离命名空间，正式 Topic 不应收到回灌数据。
5. 检查节点启动日志包含 `surface=disabled`，确认使用仅平面检测配置。
6. 记录处理帧、有效帧、无效帧、最低/均值/最高净空、点云接收数、运动补偿成功数、丢帧数和插值失败数。
7. 对至少一段静止样本、一段车辆动态样本和一段手动停止产生的短样本重复上述检查。

## 5. 通过标准

| 项目 | 通过标准 |
| --- | --- |
| 输入完整性 | 原始点云和原始高频里程计消息数均大于 0 |
| 算法配置 | 日志明确显示 `surface=disabled` |
| 结果链路 | `processed_frames > 0`，状态为 `completed`，`last_error` 为空 |
| 运动补偿 | 动态样本 `interpolation_failure_count = 0`；如非 0 必须逐帧解释，不能作为正式通过 |
| 处理覆盖 | `processed_frames / 原始点云帧数 >= 95%`；首尾边界或 KeepLast 实时策略造成的少量丢帧必须在诊断中有计数 |
| 数值有效性 | 隧道内样本至少存在 1 帧有效净空，且最小值、均值、最大值均为有限数 |
| 失败可诊断性 | 无结果时错误信息包含运动补偿接收/处理计数，并附运动补偿日志末尾 |
| 隔离性 | 不写入正式任务数据库，不改变正式任务状态，不把保存的在线净空结果当作离线结果 |

## 6. 2026-08-23 回归结果

在当前 RK3588 上对故障样本 `raw-cloud_20260823_160031_ba50d8` 使用仅平面检测配置回放：

| 指标 | 结果 |
| --- | ---: |
| 原始点云 | 117 帧 |
| 运动补偿接收/成功 | 113 / 113 帧 |
| 离线净空结果 | 113 帧，全部有效 |
| 运动补偿插值失败 | 0 帧 |
| 最低净空 | 1.4463 m |
| 平均净空 | 1.4736 m |
| 最高净空 | 1.5021 m |
| 最终状态 | `completed` |

覆盖率为 96.6%，达到本方案标准；运动补偿内部丢帧和插值失败均为 0。该结果是在雷达、RTK、正式实时算法和网页服务同时运行时，通过真实 HTTP 接口触发并离线重新计算所得，不是从 `algorithm_10hz.mcap` 读取的在线结果。

## 7. 发布前自动化检查

```bash
python3 -m pytest -q backend/tests/test_dev_offline_replay.py
```

自动化测试至少覆盖：隔离 Topic、分频播放器命令、位姿播放器先启动且实际等待预填充、无结果错误包含诊断、算法节点提前退出和停止后进度冻结。自动化测试通过不能替代第 4 节的真实 MCAP 回放。
