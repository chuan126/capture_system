## 1. 测试范围

本次验证完整首版链路：

```text
ODIN1 Lite SLAM点云
→ cloud_visualization_node
→ 轻量PointCloud2
→ FastAPI ROS桥
→ PCV1 WebSocket
→ Chromium
→ Three.js GPU点云
```

雷达和主机静止，测试时间较短，不证明动态车辆、隧道场景、Wi-Fi弱信号或30分钟
稳定性。

## 2. 软件和启动

本次使用：

- ODIN1 Lite，SN `P040100010`；
- SDK `2.0.2_20260518`，固件 `2.0.2`；
- ROS 2 Humble；
- FastAPI `0.141.0`；
- Uvicorn `0.52.0`，单worker；
- Three.js `0.180.0`；

启动顺序：

```text

→ scripts/operation/run_web.sh
```

设备有线地址为 `192.168.1.200`，页面通过
`http://192.168.1.200:8000/` 返回HTTP 200。

## 5. 实际浏览器结果

使用设备当前桌面的Chromium加载FastAPI同源页面，确认：

- 页面静态资源正常加载；
- WebSocket进入“实时点云”状态；
- Three.js WebGL上下文创建成功；
- 显示10,000个蓝色点；
- 网格、XYZ坐标轴和轨道相机正常；
- 点云呈现当前室内场景空间形状；
- 页面显示 `frame: device0/odom`；
- 页面不再显示车辆局部坐标结论。

无图形显示环境的纯headless Chromium无法创建WebGL，页面能够显示明确的WebGL
失败状态；连接到设备桌面X显示后实际渲染成功。这不影响从电脑浏览器访问，
电脑端仍需启用WebGL。

## 6. 多客户端和故障隔离

初次测试同时连接两个WebSocket客户端，两者各正常接收12个二进制点云帧。
客户端上限调整为四个后再次实测：

- 四个客户端均收到真实的120,024字节PCV1点云帧；
- 第五个客户端收到 `CLIENT_LIMIT_REACHED` 状态；
- 第五个客户端使用关闭码1013断开；
- 不影响前四个连接。

测试客户端断开后再次检查：

- `cloud_visualization_node`仍在运行；
- `/capture/visualization/cloud_preview`仍有发布端；
- FastAPI ROS桥仍保持订阅；
- 雷达和核心ROS链路未停止。

## 8. 联调中发现并修复的问题

1. ROS环境脚本会读取未定义的可选变量，与Shell `nounset` 冲突。启动脚本现在
   只在加载ROS环境期间关闭 `nounset`，之后立即恢复。
2. 虚拟环境缺少NumPy时，`PointCloud2` Python类型无法载入。已把
   `numpy==1.26.4` 加入设备运行依赖。
3. Python 3.10的 `asyncio.wait_for` 超时类型需要显式捕获
   `asyncio.TimeoutError`。已修正空队列等待路径。

## 9. 当前结论

首版已经能够从实际雷达把SLAM点云送到局域网页面并由Three.js绘制。电脑与
RK3588处于同一网段时可访问：

```text
有线：http://192.168.1.200:8000/
Wi-Fi：http://192.168.8.120:8000/
```

仍需后续完成动态车辆、真实隧道、Wi-Fi弱信号和至少30分钟连续运行验收。
