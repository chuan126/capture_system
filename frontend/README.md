# 隧道净空测量显控终端前端

核对日期：2026-08-24

前端使用 Next.js、React 和 Three.js，设备构建输出为静态文件，由 FastAPI 同端口
托管。客户版导航包含采集首页、数据回放和报告导出。development 构建额外包含“测试”工作台，customer 构建的模块图和静态产物均不包含该工作台。独立任务管理页面已经删除。

## 1. 采集首页

### 1.1 顶部系统状态

顶部左侧显示系统总状态，并提供两张摘要卡片：

- 净空高度：顶部摘要显示 `lidar_to_top_m + 雷达安装高度`。`clearance_engine` 和实时曲线继续保留原始 `lidar_to_top_m`，正式任务记录的 `clearance_height_m` 保存安装高度修正后的净空高度；
- RTK 定位：显示原始 RTK 的 WGS84 纬度、经度和高度，并附带卫星数和
  HDOP/PDOP。没有有效 RTK 时经纬高显示 `--`；
- 净空高度低于任务阈值时，当前净空高度数值直接变为红色；恢复正常后使用默认颜色。

顶部右侧以 2×2 排列雷达、RTK、主控板和数据存储。连接灯使用明确设备证据判断，
绿色表示已连接，红色表示未连接或诊断流超时。前端不会把 `warn` 一律解释为连接。
系统状态快照超过 5 秒未更新时清空旧值。

### 1.2 点云和地图

点云预览通过 `/ws/v1/cloud-preview` 接收 PCV2 分类帧（兼容PCV1），只提供三维交互视图。
坐标语义固定为雷达原始 X-Y-Z，界面轴标签显示 `X`、`Y`、`Z`。页面不再提供沿 X 轴
俯视或断面视图，也不显示旧的底部坐标状态栏。

点云和高德地图均提供右上角放大按钮。放大时使用页面遮罩，并支持再次点击、点击
遮罩或按 `Esc` 退出。

高德地图使用 `/ws/v1/rtk` 的原始 WGS84 坐标，在前端转换为 GCJ-02，并只绘制蓝色 RTK
轨迹。RTK 无效时保留最后有效地图位置但不新增轨迹点，不再回退到已删除的融合定位。
RTK连接提升到首页根组件，切换到数据回放、报告导出或测试页面时仍持续接收有效坐标；
已接收轨迹不按时间裁剪，重新进入采集首页后完整重绘，当前定位使用蓝色圆点表示。

### 1.3 原始 RTK

顶部 RTK 定位栏显示原始卫星定位：

- 纬度、经度和高度；
- 卫星数和 HDOP/PDOP。

融合定位和航位推算已删除。测试页只显示原始 RTK 卡；采集首页原任务状态卡扩展到释放的
侧栏区域。浏览器不会用 ODIN 位姿伪造 RTK 失锁期间的位置。

入口坐标和出口坐标未在当前页面显示。进出洞稳定窗口尚未实现，前端不得用当前
fix 伪造入口或出口结论。

### 1.4 任务控制卡片

采集首页任务卡片只保留“创建任务”入口。创建窗口每次只录入一个任务，填写隧道编号、隧道名称、作业车道、高度下限阈值和高度上限阈值。点击“保存并继续创建”时，当前任务必须先成功写入后端，页面才清空进入下一项。后端为每条任务生成稳定 UUID 和创建时间显示编号，例如 `20260807_145601`；同一秒连续创建多个任务时追加 `_02`、`_03`。删除历史任务不会改变或重置后续编号。

任务控制通过 FastAPI HTTP 接口连接设备端 `task_manager`。前端不直接创建 ROS 2客户端，也不自行把任务改为采集中、已暂停或已停止。

卡片结构：

1. 作业参数栏：雷达安装高度、作业车道、高度下限阈值和高度上限阈值，采用双列两行排版；
2. 当前任务：时间编号、隧道编号、隧道名称、车道和文字状态；
3. 待测任务：按创建时间正序显示。连续创建任务时，当前任务保持为最早尚未执行的任务；设备端确认任务完成后再自动选择下一项；
4. 固定控制区：开始采集、暂停或继续、停止。

开始时，前端提交当前车道、雷达安装高度、高度下限阈值和高度上限阈值，由设备端冻结参数。四项参数在约 16 英寸笔记本视口下保持两列布局和 40 px 高控件，卡片中部滚动，底部控制按钮固定可见。两个阈值的范围均为 `[0, 20] m`，并要求下限阈值不大于上限阈值；高度上限阈值默认 `20 m`。开始流程显示雷达初始化、入口 RTK 快照、记录文件创建和正式记录阶段，但不等待雷达或 RTK 真实数据确认。入口 RTK 无有效坐标时显示“坐标未确认”，任务仍继续。

暂停只停止正式测量样本写入，实时点云、RTK、净空值和设备状态继续更新。停止时固定记录边界、自动保存出口 RTK 快照并完成数据库收尾。开始和停止均为单击执行。设备端确认任务完成后，前端按创建时间自动选择下一项待执行任务，不自动开始。

任务状态和阶段通过 `/ws/v1/task-status` 更新。页面刷新后从后端恢复任务。过渡阶段异常时停止或恢复控制保持可用，设备端看门狗负责释放异常活动状态。

### 1.5 净空曲线

`/ws/v1/clearance` 提供单帧算法结果。页面保留最近 120 帧，遇到无效帧时曲线断开，
不会沿用旧值。实时曲线继续直接显示 `lidar_to_top_m`。顶部摘要使用 `lidar_to_top_m + 雷达安装高度`，只有位于“高度下限阈值 ≤ 净空高度 ≤ 高度上限阈值”的值属于正常；低于下限阈值或超过上限阈值时当前净空数值均显示红色并标明原因。正式记录不回写算法结果，而是在独立字段 `clearance_height_m` 中保存安装高度修正后的净空高度。

## 2. 数据回放和报告导出

两个页面直接使用 FastAPI 返回的设备端持久化任务列表，不再要求选择作业批次。前端只调用同源 HTTP 接口，不直接访问 ROS 2。任务停止后，采集首页当前任务卡片提供“查看数据”和“报告检查”入口。

### 2.1 数据回放

净空曲线首次显示时锁定纵轴范围。水平拖拽、横向缩放以及局部数据刷新不会自动改变
纵轴上下限，避免曲线在移动过程中上下跳变。拖拽曲线可同时左右、上下平移；界面不再提供
“适配当前窗口”按钮，纵向范围通过 Y＋、Y－和复位控制。超出锁定范围的有效点会在曲线
顶部或底部显示提示，不会静默隐藏异常。

页面结构包括：

- 左侧按创建日期分组的任务搜索、状态筛选和任务选择；
- 中部当前任务按50 Hz最近源帧保持样本显示净空高度曲线；
- 右侧隧道信息、测量统计、入口与出口 RTK 和数据质量。

数据回放首次只通过 `/api/v1/tasks/{task_id}/measurements/series-prefix?max_samples=2000` 读取每任务独立 SQLite 测量文件的开头固定样本。prefix 提交后立即显示曲线，完整统计随后异步读取；初始化视窗和任务对象刷新都不会重复请求 prefix 或触发全范围 series。用户主动平移、缩放后才按真实源时间窗口请求 `measurements/series`。已经加载的窗口按 `sample_index` 合并保留在当前任务内存缓存中，回拖到分辨率足够的已加载区域不重复请求；只有未加载区域或放大后分辨率不足的区域才补充读取。曲线支持拖拽平移、滚轮缩放、按钮缩放、键盘平移和双击复位；无效采样保持断线，暂停造成的真实时间空档保持不变。宽屏下任务记录、净空曲线和统计卡使用同一网格行高度，纵轴标题采用标准图表方向。没有测量文件时显示空状态。

数据回放只向普通用户提供逻辑删除。任务可逐项勾选、按日期选择，也可以对当前搜索和筛选结果执行“全选”，然后使用“删除所选任务”。采集中和已暂停任务的复选框禁用。批量删除由 `POST /api/v1/tasks/delete-selected` 在一个数据库事务中完成；任何一个任务不满足删除条件时整批不提交。物理清理 `/api/v1/tasks/purge-data` 继续保留为维护接口，但客户数据回放页面不再提供该入口。

### 2.2 报告导出

页面保留原有两种格式，并新增一份独立的大模型辅助报告。

1. 原始数据保存TXT。面向当前任务，以设备端实际收到的IMU消息为一行，固定输出38个业务数据列；
2. 隧道净空检测汇总 PDF。由用户勾选一个或多个任务，后端只汇总其中满足正式记录条件的任务；
3. 大模型辅助分析 PDF。用户在报告页编辑 DeepSeek API地址、API Key、模型和“大模型Skill”，配置自动保存到RK3588运行目录。点击“AI报告生成”后只分析当前任务；每次点击创建一个新的持久化导出作业和一次新的 DeepSeek 对话请求，不续用上一次模型上下文。

TXT 文件名使用任务时间编号，例如 `20260807_145601_T-001_原始数据保存.txt`。PDF 文件名使用报告生成时间。报告不再依赖作业批次状态。界面测试数据、异常中断、记录不完整或无有效高度的任务不会进入正式文件。大模型报告固定先列出任务序号、隧道编号、检测车道、隧道最低净空高、可信度、记录时间和入口/出口 RTK，表格后只包含“报告分析结果”和“数据质量分析”。

大模型报告由RK3588只读流式扫描当前任务的`measurements.db`，支持数据库与WAL合计最大2 GiB。设备端先计算源帧统计、最低20帧、3组候选的前后连续证据以及IMU/RTK质量，只把固定大小的`capture-clearance-audit-v2`审计包通过一次非流式请求发送给DeepSeek，不上传SQLite文件或高频明细。`CAPTURE_DEEPSEEK_MAX_PAYLOAD_BYTES`限制审计包大小而不是数据库大小。API地址、API Key、模型和Skill保存在`CAPTURE_DATA_ROOT/settings/device_settings.json`；作业运行副本中的Key在结束后删除，不写入报告manifest。

记录器仍保留50 Hz最近源帧保持序列供实时曲线和回放使用，但TXT改为读取按IMU实际接收频率写入的`imu_samples`。38列包含记录时间、任务字段、实时/累计最低高度、端点和逐样本RTK、IMU六轴、温度、原始雷达本体系最低点、兼容姿态列及ODIN位置/四元数；缺失项显示`0`，列间固定使用4个ASCII空格。

两类 PDF 的中文均使用 `CAPTURE_PDF_FONT_PATH` 指定的宋体，ASCII 英文、数字和标点优先使用 `CAPTURE_PDF_LATIN_FONT_PATH` 指定的 Times New Roman。项目不分发受字体授权约束的 Times New Roman；未安装时使用 PDF 标准 `Times-Roman` 兼容字体。


## 3. 开发测试工作台

测试工作台只存在于 `development` 构建。浏览器仍然只访问 FastAPI 和正式同源 WebSocket，不直接连接 ROS 2。当前页面采用左右两列单页布局；净空卡显示 `selected_inlier_count` 对应的“最低簇点数”，不再显示旧 RANSAC 指标。页面复用采集首页的 `/ws/v1/rtk` 与 `/ws/v1/clearance`，不调用 `/api/dev/overview`，因此普通打开测试页不会续租 development 高频 telemetry。

主页面的综合测试样本只提供保存、停止和删除。样本可直接启动隔离的离线净空算法；播放器只放行原始点云，不等待或播放里程计，也不回灌 MCAP 内已有的在线结果。仅包含原始点云的旧样本同样可用。算法节点提前退出时编排器立即停止播放器并返回日志摘要。`raw_sensor`、`algorithm_debug`、`full_debug` 等高级录制接口继续保留用于专项旁路诊断。

核心参数由 `ros2_ws/src/bringup/config/dev_parameter_bindings.yaml` 装订。当前八项净空参数统一来自唯一的 `clearance_engine.yaml`，包括 X 检测上下限、圆柱半径、高度带、最少支持点、YZ 网格、最少占用格和最小跨度。主列表同时显示正式 YAML 与 ROS 2 实际运行值；可写值只在详情中修改，且不写回 YAML。

测试页不再包含三维点云预览。采集首页继续使用正式点云预览旁路；综合测试 MCAP 独立保存于 `CAPTURE_DATA_ROOT/dev-tests/raw-cloud/`，不会进入任务列表、历史回放或正式报告。

开发构建：

```bash
bash scripts/build/build.sh web --variant development
```

客户构建：

```bash
bash scripts/build/build.sh web --variant customer
```

customer 构建完成后脚本会扫描静态输出，发现开发接口字符串或测试页面标识时直接失败。

## 5. Wi-Fi 连接

正式侧栏提供设备 Wi-Fi 入口。打开后通过 FastAPI 请求 RK3588 上的 NetworkManager 扫描可用网络，选择 SSID 后输入密码并连接。浏览器不调用系统命令，也不保存密码。连接成功后侧栏只显示 NetworkManager 实际确认的 SSID 名称。

切换 Wi-Fi 可能导致当前浏览器连接立即中断，尤其是浏览器本身通过该无线接口访问设备时。现场网络配置优先使用有线连接。NetworkManager、无线网卡或设备端权限不可用时页面显示不可用原因，不提供模拟网络。

## 6. 高德配置

高德地图由 RK3588 设备端统一保存。采集首页实时地图面板提供“地图设置”，用户输入 Web JS API Key 和 `securityJsCode` 后，FastAPI 将配置保存到 `CAPTURE_DATA_ROOT/settings/device_settings.json`。读取配置接口不会返回安全密钥明文，其他浏览器访问同一 RK3588 时自动使用同一设备配置。`config/network/web.env` 的高德环境变量仅作为首次迁移兼容项。高德控制台仍需为 Web Key 配置实际访问设备所使用的域名或地址。


### 回放与报告页面显示尺度

数据回放和报告导出页面已针对 16 寸笔记本提高文字、图标和控件尺寸。页面会根据 CSS 视口宽度调整列布局。报告页面在中等宽度下使用上下排列，回放检查区在较窄桌面宽度下移动到主视图下方。该调整不改变采集首页布局和实时数据协议。

### 采集首页显示尺度

采集首页已采用与数据回放、报告导出一致的笔记本可读性标准。系统状态、实时测量、设备状态、RTK 指标、任务参数、任务列表和采集控制的常规文字提高到 10 至 12 px，主要测量值和任务编号保持更大的视觉层级。点云、地图和曲线区域的标题、状态标签、坐标提示、图表刻度及放大按钮同步增大。

当 CSS 视口宽度为 1181 至 1440 px 时，采集首页改为纵向滚动布局。点云与地图仍保持同一行，RTK 与任务控制移动到主测量区下方。任务控制卡片使用明确的视口相关高度，卡片中部统一滚动，标题和底部采集控制保持可见。宽度不超过 1180 px 时继续使用窄屏布局，并保留既有字体和控件尺寸。
